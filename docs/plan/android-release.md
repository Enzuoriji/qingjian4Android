# 安卓：正式发布前要过一遍

2026-09-22 建。引擎线（E1–E8）与键盘线（K1–K10）都做完了，功能上**能自用、能给测试者装**。
但「自己能装」和「能发布」之间还差一层——这份是那道坎上的清单。

**用法**：发版前从头到尾过一遍，做完的打勾。**带「硬门槛」的三条不做完不能发**。

## 一、硬门槛（不做完不能发）

- [ ] **签名密钥**：现在 `app/build.gradle.kts` 用的是**调试密钥**（注释里写着「能装能测，
      但不能拿去分发」）。要生成一个正式的 keystore（**别进仓库**，放 `dist/` 或者仓库外，
      密码走环境变量），接进 `signingConfigs`，并且**记好它的备份**——
      丢了就再也发不出能覆盖安装的更新了。
- [ ] **应用图标**（2026-09-22 用户点名要的）：现在 `res/` 下**没有 mipmap / drawable**，
      装到手机上桌面显示的是系统默认的安卓机器人。源图现成：`assets/icon/logo.png`
      （866×866，带透明通道，mac 壳的 icns 就是它生成的）。
      要做两样：**各密度的 launcher icon**（48 / 72 / 96 / 144 / 192 px）
      与**自适应图标**（前景 + 背景两层，Android 8 起）——不做自适应的话，
      有些 ROM 会给它套个白圈或者裁成方的。生成脚本照 `assets/icon/render-logo-path.py`
      的路数写一个（**生成物随仓库提交**，别人不必装 Pillow 才能构建）。
- [ ] **隐私政策**：**云联想会把光标附近的文字发到用户自己填的服务商**。哪怕缺省是关的、
      哪怕数据不经我们的服务器，国内应用商店基本都要求有隐私政策页并声明这一点。
      桌面那边 `docs/user/cloud/index.md` 已经有那套说法（「数据从本机直连用户自己填的服务商，
      不经青简」「密码框里不发」「密钥只在本机」），安卓照抄一份，并**在设置页里链进去**。

## 二、该做（不做也能发，但会难看或者挨骂）

- [ ] **无障碍（K11，2 天）**：自绘键盘对读屏软件是「一片空白」。要可用得手工把每个键的
      无障碍信息报给系统。**用户 2026-09-22 定的：推到发版前补。**
- [ ] **多厂商 ROM 真机过一遍**：小米 / 华为 / OPPO / vivo 对输入法和后台进程的限制各不相同
      （自启、省电、输入法被系统换回 Gboard）。至少要确认：装完能启用、切过去不被顶回来、
      进程被杀之后还能自己起来。
- [ ] **桌面上的入口 + 首次启用引导**（2026-09-22 用户点名要的）：
      **这条比看上去要紧**——现在这个 APK 里只有一个 `InputMethodService`，
      而**不带 launcher activity 的 app 根本不会出现在桌面上**：用户装完在桌面找不着它，
      只能自己去系统设置里翻「语言和输入法」。这不只是「不好用」，是**找不到**。

      方案（一个 Activity 兼作两者，不新开页面）：
      1. `QingjianSettingsActivity` 加 `MAIN` / `LAUNCHER` 的 intent-filter（`exported="true"`），
         桌面图标点开就是它。
      2. 进去先**看状态**，分三种：
         - 还没启用 → 顶上一条「青简还没启用」+ 按钮，跳 `Settings.ACTION_INPUT_METHOD_SETTINGS`
           （直接落到那一页，不用用户自己找）
         - 启用了但没切过来 → 「切换输入法」按钮，`InputMethodManager.showInputMethodPicker()`
         - 都好了 → 那条不显示，直接是设置页本身
      3. 状态每次 `onResume` 重新查（用户可能刚从系统设置回来）：查
         `InputMethodManager.getEnabledInputMethodList()` 里有没有自己。

      图标点开是设置页、而不是一个「主界面」——输入法本来就是这么长的，
      不用为了「像个 App」再做一个空壳首页。
- [ ] **用户文档的安卓页**：`docs/user/` 现在整份都是桌面（macOS / Windows）的。
      安卓的安装、按键、设置要各写一份，或者在现有页里分平台。
- [ ] **应用商店的资料**：描述、截图（各尺寸）、分类、内容分级。

## 三、功能上还缺的（用户 2026-09-22 盘过，都不阻塞发布）

| 缺什么 | 说明 |
|---|---|
| 按键音 | 没做。主流输入法多半默认静音，所以一直没主动加；要做的话照着 `[keyboard]` 那节再加一项 |
| 空格长按切输入法 | 没做。安卓上挺常见的手势（Gboard 是长按地球键，很多国产输入法是长按空格） |
| ~~候选条的「展开面板」~~ | **✅ 做完**（2026-09-23，K13 ①）：长按候选条弹一块多行网格盖住键盘，几十个候选一屏看得见，点一格上屏、返回收起 |
| 剪贴板的三处毛病 + 清空二次确认 | **已排期**（同上的 K14）：左滑删除没提示、清空后又被记回来一条、带换行的条目显示成白框；清空手滑一下就没了，要 5 秒内二次确认 |
| ~~表情分类只能点箭头翻页~~ | **✅ 做完**（2026-09-23，K13 ②）：箭头去掉，一屏五个分类；滑过半页翻一整页并选中新页第一类、下面的表情跟着换，不跟惯性 |
| 问字 / 翻译选中文字 / 云释义兜底 | 云联想只接了**组句联想**那一半，这三样桌面有（见 `android-engine.md` 的 E8） |
| E9 本地整句小模型 | 排期里标着「先不做」：54 MB 模型 + candle 运行时，包体和编译复杂度都上一个台阶 |

## 四、发版流程（现在还没有）

- [ ] **构建脚本出正式包**：`scripts/build.sh` 现在固定 `--release` + 调试签名。要加一条
      「正式包」的路：正式 keystore、**两个 ABI 都带**（或者按商店要求拆 APK / 出 AAB）、
      版本号从 git 标签来（照桌面那两个壳的规矩，见 `docs/contributing.md`）。
- [ ] **发版前的验证清单**：装在一台**干净的**设备上（不是开发机）从零走一遍——
      启用输入法、打字、选词、切页、设置页每一项、云联想的「测试连接」。
- [ ] **SHA256 与校验**：产物算哈希写进发布说明（`export-device-apk.bat` 已经会打印，
      正式流程照这个来）。
- [ ] **更新日志**：CHANGELOG 手写（发版时维护者统一改，PR 不动它）。

## 五、几个数字，发之前对一眼

| | |
|---|---|
| APK | **65 MB**（arm64）/ 67 MB（x86_64） |
| 首次唤起解包 | 约 **118 MB** 解到应用私有目录（emoji 字体、词表、语言模型、释义表、领域词库），装完第一次开键盘要等约 0.6 秒 |
| 权限 | `VIBRATE`、`INTERNET`（云联想，缺省关） |
| minSdk / targetSdk | 29 / 36 |
| ABI | arm64-v8a（真机）、x86_64（模拟器） |

包体这条不用慌：Google Play 的上限是 100 MB（AAB 的话更大），国内商店更宽松 ✓

## 六、用户 2026-09-22 点名要的

这三条都不是「锦上添花」，是**发版绕不过去**的——前两条尤其：

1. **应用图标用现成那个 logo**（`assets/icon/logo.png`，866×866 带透明）→ 落在第一节。
2. **桌面上得有本体**：现在装完在桌面**什么都没有**——这个 APK 里只有一个
   `InputMethodService`，而不带 launcher activity 的 app 压根不会出现在桌面。
   用户找不到它，只能自己去系统设置里翻。→ 落在第二节。
3. **引导用户去启用输入法**：启用 + 切过来这两步，安卓上对新用户来说都不直观
   （要翻「语言和输入法 → 当前输入法」）。→ 与第 2 条合成一个 Activity，落在第二节。
