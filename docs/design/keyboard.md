# 安卓软键盘（2026-09-18）

## 起因

安卓壳要能在手机上真正用起来，就必须有软键盘。工程里此前**没有任何键盘代码**——macOS 与 Windows 是桌面系统，用户手上有实体键盘，输入法只需要弹候选窗。安卓是第一个「用户手上没有键盘」的平台，软键盘得从零做。

截至本文，安卓壳只到 Phase 1：能把引擎跑起来、候选能算出来，但界面是一行临时文字，按键还没接上。

## 已经定下的

- **键盘是「显示面」，与候选窗同路**：由 `crates/qingjian-render` 自绘成位图，各平台只贴图。理由与候选窗一致（主题一套管到底、像素级一致），见 [rendering.md](rendering.md) 的分类表——那里已经把「手机键盘面板」列进显示面。
- **命中测试在 Rust 里做**，壳只做两件事：把位图贴上窗口、把触摸坐标传回来。
- **参考 fcitx5-android（LGPL-2.1），只学交互、不抄代码**。理由见下节。
- **布局用 26 键全键盘**（2026-09-18 定），不做九宫格。理由：引擎收输入是 `Engine::push(char)`，26 键与它 1:1 对应、零改动，且与既有的双拼 / 注音 / 简拼（都是 26 键方案）相容；九宫格本质是引擎层要新增一套「一键对多字母」的歧义输入模型，不是键盘层的事，等 26 键这条路走通后单独评估。

```text
  q   w   e   r   t   y   u   i   o   p
    a   s   d   f   g   h   j   k   l
      z   x   c   v   b   n   m    ⌫
  123   中/英     空格      ，     回车
```

- **候选区做成贴在键盘上方的通栏候选条**（2026-09-18 定），不做桌面那种跟光标跑的悬浮面板。理由：桌面候选窗能浮在任意位置，安卓上键盘占着屏幕下方、悬浮面板要么被手指挡住要么遮住应用内容；通栏条是所有主流安卓输入法的形态，且渲染器已有的横排候选（`renderer/horizontal.rs`）与拼音行（`renderer/top_line.rs`）拼起来就接近它。

```text
├────────────────────────────────┤ ← 键盘顶边
│ ni'hao                         │ ← 拼音行
│ 1 你好   2 你   3 拟   4 尼  ›  │ ← 候选条
├────────────────────────────────┤
│  q   w   e   r   t   y   u  …  │
│ 123  中/英   空格   ，   回车   │
└────────────────────────────────┘
```

- **候选条与键盘各自出一张位图**，安卓侧放在同一个视图里上下拼（2026-09-18 定）。理由：候选条每敲一键都要重画，键盘只在切布局时变，揉成一张图等于每敲一个字母都把三十个键重画一遍。

### 为什么只参考不抄

fcitx5-android 的键盘是**安卓原生控件**搭的（`KeyView` / `KeyDrawable` / `CustomGestureView` 等，2636 行 Kotlin），与「整个键盘出自绘位图」是两条路，代码套不进来。

另外它虽是宽松的 LGPL-2.1（与本项目的 GPL-3.0-or-later 方向相容，不同于被移除的雾凇拼音 GPL-3.0-only），但搬代码前仍应确认许可；**只学思路则完全不存在这个问题**。

它的价值在于暴露了软键盘的**隐藏复杂度**——见下文「手感清单」，每一条在自绘路线下都要自己重写。

## 关键设计问题：桌面是键盘驱动，手机必须触摸驱动

`candidate-ui.md` 的「按键约定」表规定的是**实体键盘**上的操作。手机上这些键一个都没有：

| 操作 | 桌面用什么 | 手机上 |
|---|---|---|
| 移动高亮 | 上 / 下方向键 | 没有方向键 |
| 翻页 | `[` `]` / PageUp | 没有 |
| 选第 N 个候选 | 数字键 1–9 | 软键盘上打数字别扭 |
| 删候选 | ⇧ + 数字 | 没有 Shift 组合 |
| 上屏译词 | ⌥ + 数字 | 没有 |
| 删一个音节 | ⌥⌫ | 没有 |
| 移动拼音光标 | 左 / 右方向键 | 没有 |
| 接受整句补全 | Tab | 没有 |

**所以安卓键盘不是把桌面那套键搬过来，而是要给每个操作重新找一个触摸动作。** 映射如下（2026-09-18 定）：

| 操作 | 桌面上 | 安卓上 | 状态 |
|---|---|---|---|
| 选词 | 上下键移高亮 + 空格 / 数字 1–9 | **直接点那个候选词** | 定 |
| 翻页 | `[` `]` / PageUp | **候选条上左右滑**，右端画 `›` 作提示 | 定 |
| 接受整句补全 | Tab | **点那条整句**（它本来就在第一位） | 定 |
| 清空拼音 | Esc | **候选条右端的 `×`**（有拼音时才出现） | 定 |
| 临时大写 | 按住 Shift | Shift 键**单击锁定**（安卓标准做法） | 定 |
| 中 / 英切换 | Caps Lock 位置 | 键盘上的**中 / 英键，切青简自己的中英模式**；切到别的输入法是安卓系统自己的事（通知栏 / 导航栏），我们不做 | 定 |
| 删一个音节 | ⌥⌫ | 长按退格 | 倾向 |
| 删候选 | ⇧ + 数字 | 长按候选词 | **本轮跳过**，先把「输入 + 选词」主干跑通 |
| 上屏译词 | ⌥ + 数字 | 待定，见下（功能条） | 待定 |
| 移动拼音光标 | ← → / ⌥← ⌥→ | **先不做**——手机上输入串短，用得上但精度要求高 | 暂缓 |
| 翻译选中文字 | ⌃⌥T | 安卓没有统一的「选中文字」概念，**先不做** | 暂缓 |
| 英文直输段 | 敲半角标点 | 需要标点面板，跟着符号面板一起定 | 待定 |

## 功能条

候选条下面留一行**功能条**，参照搜狗一类的做法：候选栏之外单独一排入口按钮，以后承载各种开关与面板（译词开关、云联想开关、表情、剪贴板……）。

本轮先只放**一个入口按钮**，点开是一组设置。青简的特色是候选旁的译词，**「显示译词」的开关就落在这一条上**。

```text
├────────────────────────────────┤ ← 键盘顶边
│ ni'hao                         │ ← 拼音行
│ 1 你好   2 你   3 拟   4 尼  ›  │ ← 候选条
│ ⚙                              │ ← 功能条（本轮只有一个入口）
├────────────────────────────────┤
│  q   w   e   r   t   y   u  …  │
│ 123  中/英   空格   ，   回车   │
└────────────────────────────────┘
```

代价是多占一行高度。另一种做法是把入口放进候选条右端（与 `›` 并排）不占额外高度，但塞得挤。**定为单独一行**（2026-09-18）：手机竖直空间够，而这一条以后要长东西（表情、剪贴板、语音……）。

## 键盘上必须有的东西

从 `candidate-ui.md` 的按键约定倒推，功能上少不了的：

| 类别 | 具体 |
|---|---|
| 字母 | 26 个，另加 `'`（拼音隔音符号） |
| 上屏 | 空格（上屏高亮候选）、回车（上屏拼音原文） |
| 编辑 | 退格（删字母）、清空 |
| 模式 | 中 / 英切换（桌面是 Caps Lock 位置）、Shift（临时大写） |
| 标点 | 中文模式转全角（`，。？！：；（）`），`"` `'` 成对切换 |
| 布局切换 | 字母 / 数字 / 符号 |
| 候选交互 | 选词、翻页、删词、（译词上屏？） |

## 手感清单（fcitx5-android 的做法，自绘下都要自己实现）

| 它的实现 | 体验 |
|---|---|
| `KeyView` + 预览气泡 | 按下时键上弹出放大的气泡，防按错 |
| `SwipeSymbolDirection` | 在键上往上下滑出另一个符号（可配置方向） |
| `SpaceLongPressBehavior` | 长按空格：切输入法 / 切换 / 开表情面板（可选） |
| `CapsAction` | 大小写锁定 |
| `LayoutSwitchAction` | 字母 / 数字 / 符号三套切换 |
| `MoveSelectionAction` / `DeleteSelectionAction` | 候选条上直接选、删 |
| `PickerSwitchAction` | 表情、剪贴板这类弹出面板 |
| `KeyboardHeightPercentBase` | 键盘高度可调 |

## 待定

### 本轮不做（明确记账，不要默认它们不存在）

- **数字选词**（2026-09-18 定）：直接点候选更快，键盘上省掉数字行。桌面的「数字 1–9 选第 N 个」随之作废。
- **无障碍**：自绘键盘对读屏软件是「一片空白」，要可用就得手动把每个键的无障碍信息报给系统。**先不做，但记账**。
- **移动拼音光标**、**翻译选中文字**、**删候选（长按）**、**上屏译词的手势**：见上表。
- **符号 / 标点面板**：中文标点要转全角，英文直输段要半角标点，都依赖一个标点面板。键盘上先只放一两个常用标点键。
- **九宫格**：引擎层的新能力，不在键盘这一层解决。

### 本轮的验收标准

**能打字、能选词**：敲字母 → 候选条出候选 → 点候选上屏 → 拼音清空。其余都后补。
