# 安卓软键盘（2026-09-18）

## 起因

安卓壳要能在手机上真正用起来，就必须有软键盘。工程里此前**没有任何键盘代码**——macOS 与 Windows 是桌面系统，用户手上有实体键盘，输入法只需要弹候选窗。安卓是第一个「用户手上没有键盘」的平台，软键盘得从零做。

截至本文，安卓壳只到 Phase 1：能把引擎跑起来、候选能算出来，但界面是一行临时文字，按键还没接上。

## 已经定下的

- **键盘是「显示面」，与候选窗同路**：由 `crates/qingjian-render` 自绘成位图，各平台只贴图。理由与候选窗一致（主题一套管到底、像素级一致），见 [rendering.md](rendering.md) 的分类表——那里已经把「手机键盘面板」列进显示面。
- **命中测试在 Rust 里做**，壳只做两件事：把位图贴上窗口、把触摸坐标传回来。
- **参考 fcitx5-android（LGPL-2.1），只学交互、不抄代码**。理由见下节。
- **布局用 26 键全键盘**（2026-09-18 定），不做九宫格。理由：引擎收输入是 `Engine::push(char)`，26 键与它 1:1 对应、零改动，且与既有的双拼 / 注音 / 简拼（都是 26 键方案）相容；九宫格本质是引擎层要新增一套「一键对多字母」的歧义输入模型，不是键盘层的事，等 26 键这条路走通后单独评估。

```text
  1   2   3   4   5   6   7   8   9   0   ← 键上角的角标，**长按这个字母键**弹出「大写 / 它 / 小写」三格来选
  q   w   e   r   t   y   u   i   o   p
   @   *   +   -   =   /   #   (   )
    a   s   d   f   g   h   j   k   l
    '   :   "   ?   !   ~   \
      ⇧  z   x   c   v   b   n   m  ⌫
  符  123  ，  空格  。  中/英  回车
```

- **键预览气泡也是自绘位图，壳只负责把它贴到一个浮动小窗上**（2026-09-20 做 K5 时定）。
  气泡要弹到键盘**上方**去，而输入法窗口只有输入视图那么高，画在键盘位图里会被裁掉。
  那条「在键盘上方常驻一条透明带」的路不要：输入法窗口会盖住它，**既占屏幕又吃触摸**
  （点在键盘正上方会没反应），跟「候选条没组句就收起来」正好相反。
  所以走：**渲染器出一张带阴影的小位图**（`renderer/keyboard/popup.rs`），
  安卓侧用 `PopupWindow` 承载（`KeyPopup.kt`）——画还是我们画，壳不参与画、也不做布局计算，
  「显示面自绘」那条线没破。摆哪儿由 `Keyboard::popup_origin` 算好（气泡内容底边贴键顶、
  水平正对键心，边上的键往里夹住不出屏）。
  **气泡上写的是「这一下真正会打出去的东西」**：在键上滑出角标之后，气泡改显示那个角标
  （按住 `y` 下滑，气泡写 `6` 而不是 `y`）——气泡的用处就是让人确认会打出什么，写错了就是骗人。

- **空格「撑满」这一行剩下的宽度，不按单位宽排**（2026-09-20 定，[`KeyWidth::Fill`]）。
  缘起：最下一排只有 7 个键（6 条缝），第 1 行有 10 个（9 条缝）——**按固定单位宽排下来整排窄一条**，
  两头各缩进去半个键，跟上面几行对不齐。让空格吃掉多出来的那一段，两头就严丝合缝了。
  现在这一排是 `符(1.5) 123(1) ，(1) ｜空格（撑满）｜ 。(1) 中/英(1) 回车(1.5)`，
  空格左右各 3.5 个单位、**正落在这排正中**。
  做法照 fcitx5-android：它的空格键 `percentWidth = 0`，代码里写着 `0f means fill remaining space`。
  两头的键 1.5、中间四个 1——**「符」比隔壁的「123」宽，是让空格居中的代价**；
  试过六个键一样宽（空格改 4），那样回车只剩 1.0，太窄，退回来了。
  这块**来回错过四次**（三次是凭眼睛看走眼），现在有三条测试盯着：渲染层的
  `the_bottom_row_lines_up_with_the_first_row` 按像素量两头、`the_space_bar_is_centred_in_its_row`
  量空格中心的偏移、`only_the_bottom_row_has_a_filling_key` 盯结构。**别再凭感觉调。**
- **用「撑满」对齐的是哪几处**：字母页第 3 行的 `⇧` 与 `⌫`（两个，平分剩余）、
  最下一排的空格（一个）。**只有第 2 行（`asdfghjkl`）是故意不齐的**——
  窄半键的错位照实体键盘来，那是 QWERTY 的样子。数字页与符号页每行都是 5 个键，本来就齐。
- 句号是新加的 [`KeyId::Period`]，与 `Comma` 一样：**键帽跟着中 / 英走**——中文画全角
  （「，」「。」）、英文画半角（`,` `.`），交出去的**永远是半角**，转不转全角由引擎按设置定。
  画死成全角是不行的：切到英文之后键帽上写着「。」、打出来却是 `.`，那是骗人。

- **每个字母键带一个角标：长按这个键弹出「大写 / 符号 / 小写」三格来选**（2026-09-21 定，取代原先的「键上滑一下」）。
  角标表照 fcitx5-android 的 `TextKeyboard` 取（见下节「为什么只参考不抄」的补充）：
  数字行压在字母上面，另两行是打标点最常用的那些。**不是 US 键盘 Shift 上档的全表**——那套里
  `!`、`"` 这些在中文输入里用不上，占着角标反而难记。
  角标走 `KeyId::Literal`，与数字页、符号页同一个身份，全角与否照样交给引擎。
  顺带把隔音符号 `'` 找回来了：它原先住符号页，符号页改版后没了着落，现在挂在 `Z` 上。
- **空格键上横滑 = 移光标**（2026-09-20 定，当天又按手感改了一版）。
  手感是**「拖动当中就走，而且越拖越快」**：

  - **拖动当中就走**，不是等松手。松手才走的话手指得先盲拖一段、再抬起来看结果，
    没法一边看一边调——第一版就是这么写的，用户当场说不好用
  - **越远越快**：位移超过死区（8 点）之后开始走，速度随位移线性涨——
    刚过死区约 4 格/秒，拖到 80 点以上是 40 格/秒。跟桌面按住方向键连发一个手感
  - 刚越过死区**先走一格**，不然要等下一拍（最多 50ms）才有反应
  - 死区以内（8 点）仍然算「按空格」——上屏高亮候选那条路不受影响
  - 滑出空格键外也算数：空格键宽，划着划着就出去了，那不是「取消这一下」
  - 组句当中不动：那会儿输入框里是我们的拼音，挪光标该挪拼音里的位置，引擎还没这个能力

  **速度在 Rust、节拍在壳**（与长按连发同一个分工）：壳每 50ms 敲一拍、问「这一拍走几格」，
  走几格由 Rust 按位移量算。壳不必知道死区是多少、速度曲线长什么样。
- **移光标用 `InputConnection.setSelection`，绝不能用 `KEYCODE_DPAD_*`**（2026-09-20 踩过）。
  方向键在安卓上本来就是**焦点导航**用的：光标已经在头 / 尾时那个键没人消费，就会往上冒，
  把焦点挪到界面上的按钮去——真机上「在设置里滑空格，焦点跑到返回 / 删除键上」就是这么来的。
  正确做法是问出光标现在在哪儿（`getExtractedText`），算好目标位置直接 `setSelection`，
  一步到位、也不会外溢。**这个手势只动输入框里的文本，碰不到界面上的别的东西。**

- **候选条上长按不做任何事**（2026-09-20）。做过一版「长按候选 = 删词」（K8），
  真机上验的时候发现删不动——删词走 `Engine::forget`，而安卓壳没接 `Learner`、
  纯词库词本来也没学习记录可清，接上才有意义。用户说这功能没用，就整个摘掉了
  （理由与后续见 `docs/plan/android-keyboard.md` 的 K8 / K8+）。
  **现在长按候选等于「慢慢点一下」，松手照常选中那个词；节拍那半边只剩键盘上的退格连发。**
  一并摘掉的还有那条「引擎删完回一句话」的系统吐司——**别再往候选条上加依赖吐司的反馈**：
  真机上那句吐司一句都没弹出来过（厂商 ROM 拦吐司是常事），说不清是没话说还是没看见。

- **⌫ 上往上滑 = 松手把光标前面整段清掉**（2026-09-20 做 K7 时定）。
  **滑上去只是「预备」，松手才清**——滑错了还能滑回来取消。
  挑往上而不是往左：往左是「退格」本来的方向，容易跟普通退格混；往上是个独立的动作。
  **滑上去之后气泡改口说「松手清空」**：退格图标说不出「松手会怎样」，
  而气泡本来就是「告诉你这一下会怎样」的地方，正好用它讲。提示按文字宽度撑开。
  实现只用一条 `InputConnection.deleteSurroundingText(光标前面有几个字, 0)`——
  这是安卓专门干这事的 API，不用自己算选区、不会外溢成焦点移动。
  （第一版做的是「往左滑选字、松手删选中的」，用户当场说不好用，换成了这个。）
- **手势一开，那个键就不再算「按住」**（2026-09-20 踩到）。滑动取角标、空格移光标、
  退格选字都是从「按住这个键」岔出去的路。不排掉的话，滑得慢一点（超过连发门槛 400ms）
  就会一边做手势一边被长按连发删——实测把整段字都删光了。

- **取角标 = 长按字母键弹一排选项**（2026-09-21 定，照搜狗那套）。
  长按（壳的心跳按够 400ms 来问）弹出 **`[大写] [符号] [小写]`** 三格，**默认停在中间那个（符号）**；
  手指往左滑选大写、往右滑选小写，**松手输入所选**。选中的那格垫一块底色，滑到哪儿一眼看得出来。

  **为什么不再用「在键上滑动」**：那个手势真机上快打会误蹦符号，而且**治不好**——
  先是大方向从四个方向收成只认往下、阈值从 12 提到 22，都只是把概率压低；
  根子在「手指出了键 = 这一下作废」与手势阈值线是**重合**的（都在半个键宽上），
  横向没有余量可调。改成长按之后**误触面直接归零**：长按是有意的动作，快打根本按不到 400ms。
  代价是打一个符号要按住 0.4 秒——所以 `123` / 符 两页面板仍是快路。

  三个选项各走哪条路（`Chooser::fired`）：**大写走 `Literal`**（要的是「中文模式下也直接
  打出一个大写字母」——那条路会先上屏高亮候选、再把字符原样交出去，字母不在标点表里、原样透传）、
  **小写走 `Letter`**（就是「原来那个字母」，该进拼音缓冲区还进）、**符号走 `Literal`**。
  没有角标的键（⇧ / ⌫ / 空格 / 数字页那些）长按不开这一排。
- **`SWIPE` 22 点现在只剩一处用**：⌫ 往上滑清空。往上一滑就清掉光标前面一整段是**破坏性**的，
  阈值宁可高一点；那条路与「点击」的分界仍然是「手指出了键 = 作废」，没有第二层含义要抢。

- **候选区做成贴在键盘上方的通栏候选条**（2026-09-18 定），不做桌面那种跟光标跑的悬浮面板。理由：桌面候选窗能浮在任意位置，安卓上键盘占着屏幕下方、悬浮面板要么被手指挡住要么遮住应用内容；通栏条是所有主流安卓输入法的形态。

```text
├────────────────────────────────┤ ← 键盘顶边
│ ni'hao              ‹ 1/6 ›  ×  │ ← 拼音行 + 翻页与清空
│ 1 你好   2 你   3 拟   4 尼  …  │ ← 候选条
├────────────────────────────────┤
│  q   w   e   r   t   y   u  …  │
│ 123  中/英   空格   ，   回车   │
└────────────────────────────────┘
```

**候选条是渲染器里独立的一份（`renderer/bar/`），不复用桌面的横排（`renderer/horizontal.rs`）**（2026-09-18 实做时定）。
差异是结构级的：横排候选的宽高由内容量出来（窗口跟着候选变宽变高），候选条**宽度是屏幕宽、高度由主题算死**，
不按内容量。只有拼音行是直接复用的（`Renderer::draw_top_line`，分段、纠错删除线、光标、右侧补全全在里面）。

**高度只在「在不在组句」这一个开关上变**（2026-09-20 定）：

- **组句当中是定值**：候选从 0 个变 6 个不动。跟着候选数变的话，每敲一键都会把上面的应用内容顶一下
- **没组句时整条收起来**（高度 0）：省下的那一条还给应用，键盘钉在屏幕底边不动。
  一敲字母再顶出来——代价是敲第一个字母时上面的应用内容会被顶一下，**明知故犯**：
  空着一条几十点高的白带更难受，两害相权取其轻

高度里还留了一段 `TOOLBAR_HEIGHT`（现在 0）给**常驻的工具条**（切键盘、设置齿轮那一类）：
将来放上去时它**不受组句与否影响**，没打字时照样在。见 `renderer/bar/mod.rs`。

候选行是一条**能横着滚的带子**（2026-09-21 定）：每格宽度**按内容定**，只有低于
**底线宽度**（`MIN_CELL_WIDTH` 48 点——单字候选的自然宽度只有二十来点，没这条底线就成了点不着的针）
才抬上来。**不做「铺满一行」**：带子要能滚，铺满就没有滚的余地了；多长的词都装得下、一格都不会截。
格间留一条缝，否则三字词正好顶满格子、和隔壁看成一串。

按住横着拖，带子**跟着手指平移**，滚过一页自动翻页（`Session::scroll_by`）。
**拖动只是看，不上屏**——要选还得点一下（或空格上屏本页第一个）；要是「滚到哪儿就选哪个」，
一路翻看过去就没法全身而退了。右端的 `‹ ›` 仍可点，按页跳。

**一页画几个按这次打了几个音节定**（2026-09-20 改，原先写死 5；桌面一页 9 个）：

```
1 个音 → 6 个     2~3 个音 → 5 个     4 个音以上 → 4 个
```

打的音越多，候选越长、一格越占地方——一个音多半是单字，两三个音是常用词，四个音往上基本是成语或整句。
所以音少时反而多给一两个。

**这么做还买到一个便宜**：音数在整段组句里是不变的，页大小因此是个**定值**——
「第几页从第几条起」仍然是一个乘法（`page * 页大小`），翻页与页码都不用改。
换成「按宽度能塞几个塞几个」（fcitx5 那套是真去排 flexbox）就没这个便宜：
那得把**全部候选**都量一遍才知道页数，每次按键量上百条，几十毫秒就出去了。
数大数小是手感常数，只能靠真机调（`session/mod.rs` 的 `page_size_for`）。

**改之前是均分**，当初的理由是「每格触摸面积一样大，手指点的时候不用瞄」。那笔账其实站不住：
**点候选是看着字点的，不是数格子点的**，主流输入法（含 fcitx5-android 的 `FlexboxLayoutManager`）都不等宽。
更要命的是均分把格宽除死了：

```
slot     = (360 − 2×8) / 5                 = 68.8 点
格宽     = slot − column_gap(8)             = 60.8 点
画序号时 = 格宽 − 序号(≈6) − INDEX_GAP(3)   = 51.7 点   ← 16 点字号下 3.2 个汉字
```

**「超过三个字就变省略号」那条线就是 51.7 点来的**（用户报的）。去掉序号到 3.8 个字，
而四个汉字要 64 点、仍然差一点；**按内容分之后，一页里的词全装得下时一格都不会截**。
实测 `yixinyiyi`：「一心一意」完整显示，那一格也明显比两个字的宽。

**格子里不画序号**（2026-09-20 去掉）：候选条是手指点的，选哪一格靠位置不靠数字——
序号是实体键盘那套（`⇧ + 数字`）的东西，手指够不着，白占宽度。序号仍在 `Row::index` 里
（桌面候选窗要用），只是候选条不画。

- **候选条与键盘各自出一张位图**，安卓侧放在同一个视图里上下拼（2026-09-18 定）。理由：候选条每敲一键都要重画，键盘只在切布局时变，揉成一张图等于每敲一个字母都把三十个键重画一遍。
- **连发这类「按住多久」的计时归壳，但「哪个键会连发」归 Rust**（2026-09-20 做 K3 时定）。
  计时器要个时钟，安卓有现成的 `Handler`，为它给 Rust 引线程或定时器不划算；
  而「退格按住连删、空格按住不连发」是**输入语义**，跟「上档键干什么」是一类东西，
  壳不该知道。所以壳只管「这根手指按够 400ms 了」就往 Rust 问一次，Rust 再决定要不要触发。
  计时**按手指分开记**（`pointer` → 按下时刻），不是全局一个「按住的键」——
  两根拇指交替时后者会把前者挤掉，那正是 `KeyId` 命中那层早就踩过的坑。
- **键盘高度按屏幕高矮算，横屏再矮一截**（2026-09-20 改，K9）：高度 = 屏幕当前方向那一维
  的 **30%**（横屏 **49%**），夹在竖屏 `[200, 300]`、横屏 `[170, 260]` 之间。
  这两个比例是 fcitx5-android 的缺省——原先那两个定值 202 / 176 本来就是从它这儿按一台
  小屏手机换算出来的快照，所以「大屏手机上偏矮」是定值法的必然，不是调没调对的问题。
  **当初不敢用百分比的理由（平板横屏八百点高会算出一块巨无霸）用上限夹掉**，
  所以比例才敢上；下限贴着那两个老定值，小屏手机不至于比原来还矮。
  配色、缝、字号都不变——键变宽变扁是横屏本来的样子。
  壳报的是**屏幕在当前方向上的高度**（竖屏长边、横屏短边），不是 `displayMetrics` 那个高度
  ——见 `QingjianImeService.screenHeightPoints` 里的理由。
- **输入视图的宽度要按「视图量出来的」算，不是屏幕宽**（2026-09-20 踩过）。
  输入法窗口不一定占满屏幕：横屏时系统会给挖孔 / 手势区让出边上一条——
  实测 720×1280 的模拟器横过来之后，输入法窗口只从 `x=136` 起、宽 **1144**。
  照屏幕宽（1280）画，键盘会**宽出窗口、右边一整列键被切掉**。
  竖屏两者相等，所以这个坑只在横屏露出来。

- **配色与几何照主流输入法（讯飞那一类）的实机截图量，不凭感觉调**（2026-09-18 实做时定）。
  四档色：底色 `#DCE0E4`、内容键 `#FCFCFC`、功能键 `#BCC0CC`、回车 `#00BC10`；
  缝**横竖不一样宽**（横 7 点、竖 11 点，截图量出来 6.7 / 11）——行之间要透气，列之间挤一点键才够宽。
  两条容易忘的推论：**空格是内容键（白的），不是功能键**；**按下色按键本来的颜色分三档给**，
  不能所有键共用一个——功能键本来就灰，按下去换成内容键那个浅灰反而变亮了，看着像没按。
  数值都在 `theme/keyboard.rs` 的 `KeyboardTheme`。

### 为什么只参考不抄

fcitx5-android 的键盘是**安卓原生控件**搭的（`KeyView` / `KeyDrawable` / `CustomGestureView` 等，2636 行 Kotlin），与「整个键盘出自绘位图」是两条路，代码套不进来。

另外它虽是宽松的 LGPL-2.1（与本项目的 GPL-3.0-or-later 方向相容，不同于被移除的雾凇拼音 GPL-3.0-only），但搬代码前仍应确认许可；**只学思路则完全不存在这个问题**。

**一处例外，记在这里免得以后翻账**：字母键的角标表（哪个键滑出哪个字符）是照它的 `TextKeyboard`
抄的，不是自己编的——那是一张「键位 → 字符」的对照表，属于数据不是代码。选它的理由是这套映射已经被
人用过、符合直觉，自己拍脑袋定一套只会更难记。出处写在 `keyboard/layout.rs` 的 `LETTER_ROWS` 上。
**代码一行没抄**：它是安卓原生控件，我们是自绘位图，本来就套不进来。

它的价值在于暴露了软键盘的**隐藏复杂度**——见下文「手感清单」，每一条在自绘路线下都要自己重写。

## 关键设计问题：桌面是键盘驱动，手机必须触摸驱动

`candidate-ui.md` 的「按键约定」表规定的是**实体键盘**上的操作。手机上这些键一个都没有：

| 操作 | 桌面用什么 | 手机上 |
|---|---|---|
| 移动高亮 | 上 / 下方向键 | 没有方向键 |
| 翻页 | `[` `]` / PageUp | 没有 |
| 选第 N 个候选 | 数字键 1–9 | 软键盘上打数字别扭 |
| 删候选 | ⇧ + 数字 | 没有 Shift 组合 |
| 上屏译词 | ⌥ + 数字 | 没有 |
| 删一个音节 | ⌥⌫ | 没有 |
| 移动拼音光标 | 左 / 右方向键 | 没有 |
| 接受整句补全 | Tab | 没有 |

**所以安卓键盘不是把桌面那套键搬过来，而是要给每个操作重新找一个触摸动作。** 映射如下（2026-09-18 定）：

| 操作 | 桌面上 | 安卓上 | 状态 |
|---|---|---|---|
| 选词 | 上下键移高亮 + 空格 / 数字 1–9 | **直接点那个候选词** | 定 |
| 翻页 | `[` `]` / PageUp | **右端那对 `‹ ›` 按钮**（只有一页时不出现） | 定 |
| 看更多候选 | —— （触摸键盘特有）| **在候选条上横着拖**：带子跟手滚，滚过一页自动翻页；**拖动只看不选**，选还要点一下 | 定（2026-09-21） |
| 接受整句补全 | Tab | **点那条整句**（它本来就在第一位） | 定 |
| 清空拼音 | Esc | **候选条右端的 `×`**（有拼音时才出现） | 定 |
| 打标点 | `,` 等 | **键盘上的逗号键**；组句中先把高亮候选上屏（`nihao` + `，` → 「你好，」），中文模式转全角、英文模式半角 | 定 |
| 临时大写 | 按住 Shift | Shift 键**单击锁定**（安卓标准做法） | 定 |
| 中 / 英切换 | Caps Lock 位置 | 键盘上的**中 / 英键，切青简自己的中英模式**；切到别的输入法是安卓系统自己的事（通知栏 / 导航栏），我们不做 | 定 |
| 删一个音节 | ⌥⌫ | 长按退格 | 倾向 |
| 删候选 | ⇧ + 数字 | **不做**——做过「长按候选」，真机上删不动（壳没接 `Learner`），用户说没用就摘了 | 不做（2026-09-20） |
| 上屏译词 | ⌥ + 数字 | 待定，见下（功能条） | 待定 |
| 移动光标 | ← → / ⌥← ⌥→ | **空格键上左右横滑**，跟着手指走、越拖越快 | 定（2026-09-20 做 K6） |
| 删掉前面整段 | ⇧⌘← 选中再删 / 一路退格 | **⌫ 上往上滑**（滑上去只是预备），**松手把光标前面整段清掉** | 定（2026-09-20 做 K7） |
| 翻译选中文字 | ⌃⌥T | 安卓没有统一的「选中文字」概念，**先不做** | 暂缓 |
| 英文直输段 | 敲半角标点 | 需要标点面板，跟着符号面板一起定 | 待定 |

## 功能条

候选条下面留一行**功能条**，参照搜狗一类的做法：候选栏之外单独一排入口按钮，以后承载各种开关与面板（译词开关、云联想开关、表情、剪贴板……）。

本轮先只放**一个入口按钮**，点开是一组设置。青简的特色是候选旁的译词，**「显示译词」的开关就落在这一条上**。

```text
├────────────────────────────────┤ ← 键盘顶边
│ ni'hao                         │ ← 拼音行
│ 1 你好   2 你   3 拟   4 尼  ›  │ ← 候选条
│ ⚙                              │ ← 功能条（本轮只有一个入口）
├────────────────────────────────┤
│  q   w   e   r   t   y   u  …  │
│ 123  中/英   空格   ，   回车   │
└────────────────────────────────┘
```

代价是多占一行高度。另一种做法是把入口放进候选条右端（与 `›` 并排）不占额外高度，但塞得挤。**定为单独一行**（2026-09-18）：手机竖直空间够，而这一条以后要长东西（表情、剪贴板、语音……）。

## 键盘上必须有的东西

从 `candidate-ui.md` 的按键约定倒推，功能上少不了的：

| 类别 | 具体 |
|---|---|
| 字母 | 26 个，另加 `'`（拼音隔音符号） |
| 上屏 | 空格（上屏高亮候选）、回车（上屏拼音原文） |
| 编辑 | 退格（删字母）、清空 |
| 模式 | 中 / 英切换（桌面是 Caps Lock 位置）、Shift（临时大写） |
| 标点 | 中文模式转全角（`，。？！：；（）`），`"` `'` 成对切换 |
| 布局切换 | 字母 / 数字 / 符号 |
| 候选交互 | 选词、翻页、删词、（译词上屏？） |

## 手感清单（fcitx5-android 的做法，自绘下都要自己实现）

| 它的实现 | 体验 |
|---|---|
| `KeyView` + 预览气泡 | 按下时键上弹出放大的气泡，防按错 |
| `SwipeSymbolDirection` | 在键上往上下滑出另一个符号（可配置方向） |
| `SpaceLongPressBehavior` | 长按空格：切输入法 / 切换 / 开表情面板（可选） |
| `CapsAction` | 大小写锁定 |
| `LayoutSwitchAction` | 字母 / 数字 / 符号三套切换 |
| `MoveSelectionAction` / `DeleteSelectionAction` | 候选条上直接选、删 |
| `PickerSwitchAction` | 表情、剪贴板这类弹出面板 |
| `KeyboardHeightPercentBase` | 键盘高度可调 |

## 待定

### 本轮不做（明确记账，不要默认它们不存在）

- **数字选词**（2026-09-18 定）：直接点候选更快，键盘上省掉数字行。桌面的「数字 1–9 选第 N 个」随之作废。
- **无障碍**：自绘键盘对读屏软件是「一片空白」，要可用就得手动把每个键的无障碍信息报给系统。**先不做，但记账**。
- **移动拼音光标**、**翻译选中文字**、**删候选（长按）**、**上屏译词的手势**：见上表。
- **符号 / 标点面板**：中文标点要转全角，英文直输段要半角标点，都依赖一个标点面板。键盘上先只放一两个常用标点键。
- **九宫格**：引擎层的新能力，不在键盘这一层解决。
- **英文模式的候选**：安卓上的中 / 英切换是「英文直输」（字母直接打出去，不带候选）。
  引擎的英文候选要另喂一张英文词表（`Engine::with_english`），这张表还没随包带上——
  要接得先把英文词表生成出来，属于数据的事，不在键盘这一层。

### 本轮的验收标准

**能打字、能选词**：敲字母 → 候选条出候选 → 点候选上屏 → 拼音清空。其余都后补。
